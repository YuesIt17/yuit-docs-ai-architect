Executive Summary

What this case covers

RetailPartnerX, an FMCG retailer, wants personalized recommendations and conversational commerce, but the requirements are vague: no KPIs, data boundaries or channels. The case works through the full architecture lifecycle, from discovery and the contract model to C4, agentic RAG, the data pipeline, production readiness, inference sizing, delivery automation, high-load design and FinOps governance.

What this portfolio demonstrates

AI systems treated as distributed software systems: boundaries, data flows, integrations, trust boundaries, failure modes, evaluation and trade-offs, not just a list of technologies.

Architecture design

C4 (C1–C3), Sequence, OpenAPI, multi-agent RAG, ADR LLM hosting, data pipeline, security/eval/observability, inference sizing, CI/CD and MLOps, high-load design, Model Card and FinOps: most of the artifacts.

Prototype

LangGraph stub: 6-agent flow, keyword RAG, policy deny, 7 pytest. No API keys, no real LLM or Vector DB.

What this is not

A production deployment. There is no running Kafka, Spark, Pinecone, Prometheus, Ragas CI, Terraform, Argo CD or KEDA. hw-2 sets no numeric latency SLO until MVP measurements exist; the 10k RPS and p95 < 200 ms figures in hw-9 are design targets, not measurements.

Architecture at a Glance

System architecture

Two key views: the recsys container architecture (hw-2) and the shopping assistant agentic layer (hw-3).

  • System boundaries: Backend orchestrates the UI and catalog; AI Service is a separate deployable with a REST contract
  • Major components: Ranker, RAG Manager, LLM Client (recsys); Orchestrator, Policy Analyst, Catalog Searcher (assistant)
  • Data flows: PIM/CDP → data pipeline → Feature Store / Vector DB → AI Service; synchronous request on the product page
  • Orchestration: LangGraph state machine (prototype); Supervisor pattern in the design
  • Integrations: POST /get_recommendation — Basket Assembler calls the recsys API from hw-2
  • Trust boundaries: Backend has no knowledge of ML details; PII Sanitizer before the LLM; Secret Manager for API keys
  • Security: Input Guard (prompt injection), Output Guardrails, Policy Analyst semantic guard
  • Observability: Prometheus + Tempo + Langfuse → Grafana (design, not deployed)

Enterprise / Retail Context

Applicability to enterprise retail

The architecture patterns in this case can be applied to typical FMCG / grocery retail problems, without being tied to any specific production system.

Product recommendations

A “Frequently bought together” block on the SKU page, with Ranker → Top-K → LLM re-rank and latency budget control.

Shopping assistant

Conversational commerce: constraint parsing (allergens, budget, promotions) and basket assembly through the recsys API.

Policy compliance

RAG over internal policies (GDPR, 18+, allergens) as a semantic guard, with Policy Analyst isolated for audit.

Knowledge freshness

Data pipeline that keeps the Product KB, embeddings and online features current, linking Faithfulness to hw-5 freshness.

Enterprise copilots

The Supervisor multi-agent pattern applies to internal knowledge workflows with explicit guardrails and evaluation.

Supplier workflows

Dual KB architecture (operational data + policy docs): a pattern for separating retrieval strategies.
